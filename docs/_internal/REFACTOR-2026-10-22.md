> 目的：以**当前工作区**（v2.12 + 字体/许可/动画改动）为基线，系统盘点结构性问题与改进空间，

## 3. 领域改进清单（R-编号）

> 格式：问题 → 建议 → 影响（装置/体验/工程）/ 成本（S≈1 天、M≈3–5 天、L≈1–2 周）。

### 3.1 渲染与引擎（R1–R10）

| ID | 改进项 | 建议 | 影响 | 成本 |
|---|---|---|---|---|
| R1 | 视锥剔除默认常开但**无开关、无 draw 计数**，无法 A/B 也无法解释性能变化 | 加 `--cull 0/1` + 每帧 draw/实例计数打点，接进 `[perf]` 日志 | 性能诊断 | S |
| R2 | 阴影只覆盖球/柱，**表面/卡通/QuickSurf 不投影** | 重构 `draw_geometry` 缓冲上传职责，让 TriMesh 进阴影 pass（`shadow_map.h` 头注释已写明） | 观感一致性 | M |
| R3 | 细分档是**静态两档**（3/24 预览、4/48 导出） | 自适应 LOD：按投影像素直径选档（`d_px<6→2`、`<24→3`、否则 4） | 大场景性能 | M |
| R4 | GPU 密度核**只有头文件**：`surface.comp` + `surface_compute.h` 就绪，缺 `.cpp`、CMake 注册、`vkCmdDispatch` | 参照 `shadow_map.cpp` 建独立 compute pass；失败回退 CPU | QuickSurf 10× 级提速 | L |
| R5 | 光追：表面透明度是单次前向合成、无降噪、CLI 每次重建 BVH | 深度排序/折射近似、双边降噪、跨调用 `RtAccel` 缓存 | 出图质量/速度 | M |
| R6 | 命令流：replay 不可靠（I-30）；16 MiB 切块靠 `appendTriMesh` 隐式处理；`bumpSerial()` 靠人记 | replay 逐像素单测；切块加显式校验；serial 纪律做成断言/调试检查 | 正确性 | M |
| R7 | 异步表面：单工作线程 FIFO，**无优先级/取消**；导出用 `prepareBlocking()` 阻塞等待 | 任务优先级（可见体系优先）、取消、进度回调 | 交互体验 | M |
| R8 | Vulkan 资源生命周期靠手工 release（I-18 的纹理/描述符教训） | 统一 RAII/句柄封装 + "销毁前 device idle" 断言 | 稳定性 | M |
| R9 | 着色器在 configure 期编译，改 `.frag` 不重编易踩（已知坑） | 生成脚本加 hash stamp；加 `--shaders` 独立目标；构建日志打印 SPIR-V 时间 | 开发效率 | S |
| R10 | 渲染质量：无 SSAO/描边通道，Edgy/AO 材质靠近似；光栅与 RT 色调映射不一致 | 记录为已知限制；若要出版级，按 R2/R5 统一光照模型 | 观感 | M |

## 4. 改造方案（阶段与 R-ID 映射）

### 阶段 A（1–2 天）：正确性

1. **A1 统一坐标入口**（P0-1/R11/R15）：`SceneStructure::applyFrame(FrameView)`，
   `DisplayWrapped` / `Continuous` 两种语义；GUI 播放/导出、CLI 全部改走该入口。
2. **A2 动画帧流**（P0-1/R11）：`engine::anim::FrameStream` 负责连续缓冲 → 插值 → 显示回盒；
   GUI 暴露插值倍数。
3. **A3 replay 一致性**（P0-2/R6）：同帧 replay vs 整条重建逐像素单测；修复后去掉 CLI 强制重建。
4. **A4 动画测试**（R29/P2-1）：帧序、插值位移减半、PBC 连续性、ffmpeg 缺失回退。
5. **A5 采样语义**（P0-3/R14）：核对 XTC time 字段，明确"物理时间 → 播放率"。

**验收**：同轨迹同帧 GUI/CLI 导出 PNG 逐像素一致；CLI 动画 ≥15 fps（800×600）；动画单测入回归。

### 阶段 B（3–5 天）：可维护性与体验

- B1 大文件拆分（R19/P1-1..4）——`render_cmd`、`modules`、`workbench`、`mol_scene`。
- B2 GUI 导出后台化 + 进度/取消（P0-4/R22）。
- B3 CMake 字体 helper（P1-5）、i18n 补录与字形表（P1-6/R45）。
- B4 选择表达式校验（R23）、快捷键表（R25）、小屏适配（R26）。
- B5 工程设施：`CMakePresets`（R36）、`.clang-format`（R37）、覆盖率脚本（R34）。

**验收**：单文件 <800 行；构建 0 警告；导出可响应/可取消；i18n 缺口 <50。

### 阶段 C（1–2 周）：功能与质量

- C1 自适应 LOD（R3）、GPU 密度核（R4）。
- C2 轨迹流式加载（R12）、对齐/拟合（R16）、reader 统一（R13）。
- C3 DFT：MO 等值面 + 能级图（ROADMAP 2.2）；测量工具（R24）。
- C4 阴影 TriMesh（R2）、RT 降噪/缓存（R5）、CI + golden image（R30/R35）。

## 6. 风险登记

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 统一坐标语义改动同时影响播放/导出，引入回归 | 中 | 高 | 以"同帧逐像素一致"为门禁；分两步（先 CLI 对齐 GUI，再合并实现） |
| replay 修复触及命令流核心 | 中 | 高 | 先加一致性单测再动实现；保留强制重建开关兜底 |
| 并行会话/多人同时改同一文件 | 高（已发生） | 中 | 分支 + 每功能一提交；提交前 `git status` 核对归属 |
| LOD/拆分改变观感或行为 | 中 | 中 | 固定 golden image + 关闭 LOD 的 A/B 开关 |
| CI 引入后构建时间过长 | 中 | 低 | 缓存 vcpkg、分离 smoke/full 任务 |
| 采样语义修正改变现有视频观感 | 中 | 低 | 保留 `--anim-fps/--anim-interp`，文档说明 |
| 文档再次落后于代码 | 高 | 中 | 发布清单（R50）+ CHANGELOG 模板（R43） |

## 7. 不建议做的事

1. **为了拆分而拆分**：先拆行为清晰的模块（render_cmd/modules），不要整体重写。
2. **在没有 golden image 的情况下改渲染默认值**（光照/材质/阴影），否则"修一个坏三个"。
3. **引入 OSPRay/Embree 解决局部问题**：当前自研 BVH 已够用，依赖成本高。
