## 3. 构建 / 测试 / 运行（照做即可）

```powershell
# 1) 增量构建（Debug）：先关掉正在运行的 exe（文件占用会 link 失败）
Get-Process moleculens_app -ErrorAction SilentlyContinue | Stop-Process -Force
cmd /c "F:\MolecuLens\tools\build_incremental.bat > F:\MolecuLens\build\v2_build.log 2>&1"
Select-String -Path F:\MolecuLens\build\v2_build.log -Pattern 'error C\d|error LNK|moleculens_app.vcxproj ->'

# 2) Release（给用户实际运行/截图用）
& "D:\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" `
  F:\MolecuLens\build\Moleculens.sln -p:Configuration=Release -m -v:minimal
Copy-Item F:\MolecuLens\build\vcpkg_installed\x64-windows\bin\*.dll `
          F:\MolecuLens\build\src\app\Release\ -Force      # fmt/spdlog/glfw3

# 3) 测试
F:\MolecuLens\build\tests\Debug\moleculens_tests.exe        # 期望 171 cases / 193,670 断言全过
```

**已知噪声（不是失败）**
- 每次构建都会报 `MSB3073`（vcpkg `applocal.ps1` + font `make_directory`），只要日志出现 `<target>.vcxproj -> ...exe` 就算成功。
- 应用会额外开一个 spdlog **控制台窗口**；**关闭控制台 = 直接杀进程**（只能 minimize）。
- 主窗口是无边框 GLFW，`windows maximize` 对它无效；需要 P/Invoke `SetWindowPos(hwnd,0,0,0,1920,1040,0x0040)`，再 `pwsh -File tools\capture_window.ps1 -Hwnd <hwnd> -Out <png>`。
- 桌面桌宠（`electron.exe` "dsh-pet 桌宠"）截图前要 minimize，否则会盖住检查器。

**着色器有一个大坑**：`shaders/*.frag|glsl` 在 **CMake configure 期**编译内嵌（`cmake/shaders.cmake` + `spv_to_header.py` → `build/gen/shaders/*.h`），`msbuild` 增量构建**不可靠**触发 configure。改完着色器必须显式：
```powershell
cmake -S F:\MolecuLens -B F:\MolecuLens\build
```
另外**不要**用 `Set-Content -Encoding UTF8` 改 GLSL（会写 BOM，glslang 报 `'锘? : unexpected token`）；用
`[IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`。

## 5. 场景保存「嵌入式 / 链接式」双模式（✅ 已完成）

**实现结果（2026-10-21，以 `src/persist/mlscene/mlscene.h` 为准）**：

- `.mlscene` 布局：Header(16B) → 元数据 JSON → `u64 cmdSize` + 命令流 → `u64 coordsSize` + 坐标 SoA → **可选** `u64 trajSize` + `u32 trajCount` + 每条 `{u64 frameCount, u32 atomCount, u32 flags, float32 positions[frameCount*atomCount*3], [float32 boxes[frameCount*9]]}` → CRC32(4B)；**版本仍是 2**，链接式不写该段（字节布局与旧文件一致）。
- 读侧：坐标段后需同时满足 `pos+8 <= filesize-4` 与 `pos+8+trajSize <= filesize-4` 才解析；越界 strict 报错 / lenient 跳过；旧文件缺 `mode` → 按 `linked`。
- `SceneSaveMode{Linked, Embedded}`（默认 Linked）+ `modeKey()/modeFromKey()`；`settings.json` 顶层 `sceneSaveMode`；GUI 弹「保存场景」双模式框（体积预估 + 200 MB 警告），`Ctrl+S` 与「文件 → 保存场景…」都先弹框；**CLI 仍按链接式**。
- 去重：同一 `shared_ptr<Trajectory>` 只内嵌一份（2042 实例共享 1001 帧不会按实例数翻倍）。
- 文档：01 §8.1/§8.2、02 §4.1/§7/§8、03 §4.4/§7.8；测试：8 个 mlscene/场景桥用例，全量 171 例通过。

## 6. 「打开文件」对话框看不到文件（✅ 已修复）

**实现结果（2026-10-21）**：

- `nativeOpenFileDialog()` / `saveFileDialogEx()` 改用 `GetOpenFileNameW` / `GetSaveFileNameW` + `OPENFILENAMEW`，owner = `GetActiveWindow()`（回退 `GetForegroundWindow()`），32 KiB 路径缓冲；打开标志 `OFN_EXPLORER|OFN_FILEMUSTEXIST|OFN_PATHMUSTEXIST|OFN_NOCHANGEDIR|OFN_HIDEREADONLY`（保存加 `OFN_OVERWRITEPROMPT`），`nFilterIndex=1`，打开 `defExt=nullptr`。
- `ParserRegistry::allExtensions()`（小写、去点、去重、注册顺序）成为过滤器唯一事实来源，当前 `pdb/ent/gro/sdf/mol/cube/cub`；轨迹过滤器补 `.trr`。
- 三条根因（ANSI 路径截断 / 漏 `.ent/.mol/.cub` / `std::string(const char*)` 在第一个 NUL 截断过滤器）与用户侧排障写进 03 §7.10；缺陷记录在 04 §6.7；`allExtensions()` 有单测钉住。
- **GUI 复验状态**：中文目录 `EPI.pdb` 成功载入（04 §5.9 第 4 项，已通过）；`.cube/.mol` 本机无样本，由过滤器与单测覆盖。

> 以下「现状 / 可能原因 / 修复建议」是**修复前的排查记录**，保留供溯源。

### 现状（源码事实，修复前）
- 对话框实现是 **ANSI Win32**：`nativeOpenFileDialog()`（`src/app/view/control/view_control.cpp:64-85`）用 `GetOpenFileNameA` + `OPENFILENAMEA`，过滤器由调用方给（每个过滤器必须是 `说明\0通配\0…\0\0`）。
- 工作台「打开文件」的过滤器（`Workbench::openFileDialog`）：
  `"分子结构 (*.pdb;*.gro;*.sdf;*.cube)\0*.pdb;*.gro;*.sdf;*.cube\0MolecuLens 场景 (*.mlscene)\0*.mlscene\0所有文件 (*.*)\0*.*\0"`
- 解析器实际支持扩展名（`src/io/**/**_parser.h`）：
  - PDB: `.pdb`、`.ent`
  - GRO: `.gro`
  - SDF: `.sdf`、`.mol`
  - CUBE: `.cube`、`.cub`
  - 轨迹（单独走导入）：`.dcd/.xtc/.trr`
- 旧 v1 对话框（`openFileDialog()`）还写着 `*.pdb;*.gro;*.sdf;*.mol`。

### 可能原因（按概率）
1. **ANSI 对话框 + 中文/Unicode 路径**：`GetOpenFileNameA` 在非 GBK 可表示路径或高版本 Windows 上可能异常；用户机器为中文系统，但目录/文件名可能含 emoji/特殊字符。
2. **过滤器未覆盖用户的文件类型**：例如 `.mol2` / `.xyz` / `.trr` / `.ent` / `.cub` 或大写扩展名；或用户从「导入轨迹」入口打开结构文件（反之亦然）。
3. **过滤器串格式错误**（缺双 NUL / 用了 `trItems` 的临时 c_str 悬垂）导致列表为空。
4. `OFN_FILEMUSTEXIST` + 默认目录不可访问 → 列表空白。

### 修复建议
- 换成 **Unicode 对话框**：`GetOpenFileNameW` + `std::wstring`（`MultiByteToWideChar(CP_UTF8/CP_ACP)`），或更现代地改用 **IFileOpenDialog**（推荐，支持长路径、Unicode、多选、更好的默认视图）。
- 对话框过滤器与 `ParserRegistry` **共用一个事实来源**：新增 `ParserRegistry::allExtensions()`（或从每个 reader 的 `extensions()` 收集），生成 `"支持的文件 (*.pdb;*.ent;*.gro;*.sdf;*.mol;*.cube;*.cub;*.mlscene)\0…\0所有文件 (*.*)\0*.*\0"`，避免以后新增格式忘记改 UI。
- `openFileDialogEx/openFileDialog` 增加 `OFN_EXPLORER | OFN_HIDEREADONLY`，设置 `ofn.nFilterIndex = 1`，owner 设为主窗口 hwnd（否则对话框可能被主窗口挡住，看起来像"没反应"）。
- 大小写：Windows 过滤器不区分大小写；若仍有问题，可把 `*.pdb` 与 `*.PDB` 都写上（一般不需要）。
- 复现：用用户提供的目录/文件（先问清具体路径与扩展名，或让他发一张对话框截图）。

**验收**：在中文路径 + `.cube`/`.mlscene`/`.mol` 文件上都能看到并选中；「所有文件」可见任意文件；选择后用 `moleculens-cli info` 同文件验证解析器确实支持。
