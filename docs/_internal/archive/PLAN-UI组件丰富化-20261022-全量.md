## 1. 问题诊断：为什么现在显得"单薄"

| 现象 | 技术原因 | 用户感受 |
| --- | --- | --- |
| 面板像一张长表单 | 全部参数都是"标签 + 滑块"纵向堆叠，只有 `sliderRow` 一种节奏 | 找不到重点，改一个参数要滚半天 |
| 层级扁平 | 分组只有 `sectionLabel` 一级；没有带计数/状态的折叠组 | 分不清"主设置"与"高级设置" |
| 精确调节困难 | 没有数值输入、没有步进、没有分段选择 | 想把不透明度设成 0.35 只能靠拖 |
| 没有"所见" | 材质、色标只有下拉文字，没有缩略预览 | 不知道选了会是什么样 |
| 状态缺位 | 空态/加载/错误三类状态没有统一组件，各面板自己 `Text` | 视觉不一致 |
| 密度浪费 | 检查器固定 340 px 单列，宽屏上大量留白 | 觉得"空" |
| 缺快捷提示 | tooltip 靠各控件 `tip` 参数，没有统一的 `(?)` 入口 | 新用户不知道参数含义 |

## 2. 设计语言补充（先定 token，再写控件）

### 2.1 栅格与节奏
- 基单位 **4 px**；间距只用 4 / 8 / 12 / 16
- 卡片内边距 12；卡片之间 8；分组之间 16
- 控件行高 28（与现有 ImGui FramePadding 对齐），双行列表行高 44

### 2.2 字号阶梯（复用现有字体，不加新字号文件）
| 用途 | 字号 | 字重 |
| --- | --- | --- |
| 极小标注（单位、序号） | 11 | Regular |
| 正文/表单标签 | 12 | Regular |
| 卡片标题 | 13 | Medium |
| 模块标题 | 15 | SemiBold |
| 关键数字（原子数、FPS） | 20 | SemiBold |

### 2.3 形状
- 输入框/按钮圆角 4，卡片 8，胶囊 999
- 选中态：`accentSoft` 底 + `accent` 1px 描边（不是实心，避免抢视线）
- 主操作（如"创建表面"）：`accent` 实心 + `onAccent` 文字

### 2.4 交互态
| 状态 | 处理 |
| --- | --- |
| hover | 底色亮度 +6%（`accentHi` 亦可） |
| active/pressed | +12%，圆角不变 |
| disabled | 整体 40% 透明度，禁用 tooltip 保留 |
| focus | `borderStrong` 2px（键盘可达性） |

> 全部颜色取自 `palette()`，**禁止**在控件里写死 `IM_COL32`；浅色/深色/自定义强调色三态都要过一遍。

## 6. 约束与风险

1. **全部控件走 aurora**：面板模块里不得再出现写死坐标/颜色/间距。
2. **不引入第三方 UI 库**（ImGui 单栈），所有新控件用 `ImDrawList` 现画。
3. **中英双语**：所有文案经 `tr()`；控件不得接受裸中文。
4. **高 DPI**：只用 ImGui 逻辑单位，禁止像素硬编码。
5. **三态主题回归**：浅色 / 深色 / 自定义强调色，新控件逐个截图核对。
6. **面板性能**：组件内避免堆分配（用栈缓冲与 `ImGui::PushID`），面板每帧重绘。
7. **文件拆分**：`modules.cpp` 已 1862 行，P0 阶段顺带按模块拆成 `modules_scene.cpp` / `modules_visualize.cpp` 等，单文件 < 800 行。
8. **ImGui 断言风险**：`cardBegin` 这类成对 API 的 `End` 必须在 `if` 外无条件调用（先例见 aurora.h 注释），新容器组件沿用同一约定并在头文件写清。

## 7. 建议的第一刀

`segmented` + `sliderNum` + `badge` 三个控件先行，然后只改「显示」面板的表示类型与画质档：

- 收益最直观（一眼看出"界面变专业了"）
- 风险最小（纯新增 API + 一处调用替换）
- 不触碰渲染/引擎，出问题也只影响面板

确认后我按 P0-A 直接开工。

## 实施进度 · v2.8 视图升级（2026-10-21 23:00）
